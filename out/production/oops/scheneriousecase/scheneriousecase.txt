✅Scenario 1: Online Payment System (Abstraction)✅
Use Case:
Ek e-commerce website (Amazon, Flipkart) par payment methods (Credit Card, UPI, Net Banking) handle karni hain.

Solution (Abstract Class Use Case)
Yahan hum ek abstract class bana sakte hain PaymentProcessor, jo common logic handle
kare aur har payment method ko alag implement kare.


abstract class PaymentProcessor {
    abstract void processPayment(double amount); // Abstract method

    void generateReceipt() {  // Concrete method
        System.out.println("Generating Receipt...");
    }
}

class CreditCardPayment extends PaymentProcessor {
    @Override
    void processPayment(double amount) {
        System.out.println("Processing Credit Card Payment of ₹" + amount);
    }
}

class UPIPayment extends PaymentProcessor {
    @Override
    void processPayment(double amount) {
        System.out.println("Processing UPI Payment of ₹" + amount);
    }
}

public class PaymentTest {
    public static void main(String[] args) {
        PaymentProcessor payment = new CreditCardPayment();
        payment.processPayment(500.0);
        payment.generateReceipt();
    }
}
✅ Kab Use Karen? Jab partially implemented methods aur common logic ho jo subclasses share karein.



------------------------- ✅  INTERFACE ✅ ------------------------



✅ Scenario 2: Multiple Notification Services (Interface)
Use Case:
Ek system ko Email, SMS, aur Push Notification bhejni hain, aur ye alag-alag implement honi chahiye.

Solution (Interface Use Case)
Yahan ek NotificationService interface banayenge, jisme har class apni implementation degi.


interface NotificationService {
    void sendNotification(String message);
}

class EmailNotification implements NotificationService {
    @Override
    public void sendNotification(String message) {
        System.out.println("Sending Email: " + message);
    }
}

class SMSNotification implements NotificationService {
    @Override
    public void sendNotification(String message) {
        System.out.println("Sending SMS: " + message);
    }
}

public class NotificationTest {
    public static void main(String[] args) {
        NotificationService emailService = new EmailNotification();
        emailService.sendNotification("Your order has been shipped!");

        NotificationService smsService = new SMSNotification();
        smsService.sendNotification("Your OTP is 123456");
    }
}
✅ Kab Use Karen? Jab multiple implementations chahiye ho jo ek common contract follow karein.

✅ Scenario 3: Vehicle System (Abstract Class + Interface)
Use Case:
Ek Vehicle System bana rahe hain jisme Car aur Bike dono honi chahiye,
aur sabhi vehicles ke kuch common aur kuch unique features honge.

Solution (Abstract Class + Interface)
Vehicle Abstract Class: Common logic store karega (startEngine, stopEngine).
FuelType Interface: Define karega ki fuel type kya hoga (Petrol/Diesel/Electric).


interface FuelType {
    void fuelType();
}

abstract class Vehicle {
    abstract void speed();

    void startEngine() {
        System.out.println("Engine started...");
    }

    void stopEngine() {
        System.out.println("Engine stopped...");
    }
}

class Car extends Vehicle implements FuelType {
    @Override
    void speed() {
        System.out.println("Car speed: 180 km/h");
    }

    @Override
    public void fuelType() {
        System.out.println("Car uses Petrol");
    }
}

class Bike extends Vehicle implements FuelType {
    @Override
    void speed() {
        System.out.println("Bike speed: 120 km/h");
    }

    @Override
    public void fuelType() {
        System.out.println("Bike uses Diesel");
    }
}

public class VehicleTest {
    public static void main(String[] args) {
        Vehicle myCar = new Car();
        myCar.startEngine();
        myCar.speed();
        ((FuelType) myCar).fuelType();  // Type casting

        Vehicle myBike = new Bike();
        myBike.startEngine();
        myBike.speed();
        ((FuelType) myBike).fuelType();
    }
}
✅ Kab Use Karen? Jab hierarchy ho aur multiple behaviors implement karne ho.
